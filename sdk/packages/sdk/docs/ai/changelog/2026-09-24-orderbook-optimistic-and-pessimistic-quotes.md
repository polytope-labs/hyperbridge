# 2026-09-24 — Orderbook optimistic and pessimistic quotes

The HyperFX orderbook changed its quote schema. `quote` is now optimistic. It splits the trade across the route's orders, best price first, each at its own price, and returns only `fills` (`advertisedSize`, `orderRate`, `amountIn`, `amountOut`), with no total `amountOut`, `rate` or `depth`. The new `quotePessimistic` returns a `LevelQuote`: one `rate` and `priceBucket`, from the first level deep enough to fill the trade by itself, or else the route's worst price. Every quote and `routeLiquidity` now report `slippageBps`, the destination's protocol fee. Rates are signed prices before that fee, and every `amountOut` already has it taken off.

- `HyperFxOrderbook.quote` returns the new `OrderbookSwapQuote` (`slippageBps`, `fills: OrderbookQuoteFill[]`). `HyperFxOrderbook.quotePessimistic` returns `OrderbookLevelQuote`. `ORDERBOOK_QUERIES.quotePessimistic` is the new document. `routeLiquidity` now carries `slippageBps`.
- `IntentGateway.quoteIntent` returns the orderbook's quote with amounts in raw token units, and takes `QuoteIntentParams.optimistic` to choose which. By default it queries `quotePessimistic` and returns `PessimisticQuoteIntentResult`. That result mirrors `LevelQuote`: `{ route, side, amountIn, amountOut, rate, priceBucket, slippageBps, fillable, maxFillableIn }`.
- With `optimistic: true` it queries `quote` and returns `QuoteIntentResult`, which is `{ route, side, amountIn, slippageBps, fillable, maxFillableIn, legs }`, and each `IntentQuoteLeg` is `{ advertisedSize, orderRate, amountIn, amountOut }`. `orderRate` stays a 1e18 `bigint`. There is no total output: callers sum the legs' `amountOut`.
- The previous result's `tradeType` and `quoteMetadata` are removed, along with `IntentQuoteMetadata` and `IntentQuoteTradeType`.
- Overloads narrow the return type from the literal `optimistic` value.
- Either quote throws `InsufficientOrderbookLiquidityError` when the route cannot fill the trade.
- The orderbook (0.4.1) matches token symbols and book ids without regard to case, and answers in its configured spelling. `HyperFxOrderbook` now matches the returned `books` to a route case-insensitively too. The orderbook docs page states both, and its fee convention now says rates are before the protocol fee.
- The SDK does no fee math. Exact output starts from `routeLiquidity.bestRate`. Each round keeps the fills better than the quote's worst price and re-prices the rest of the output at the worst fill's `amountIn`/`amountOut` ratio, which is the orderbook's own post-fee ratio. The worst fill is the last one for `quote` and the whole trade for `quotePessimistic`. The orderbook floors outputs, so the input can exceed the least one that delivers by under one raw output unit's worth.

Validation: simplex's pinned `orderbook-schema.graphql` is refreshed from `hyperfx-orderbook` main. `orderbookSchema.test.ts` validates both quote documents and the docs page examples against it. `orderbookMarket.test.ts` stubs a two-level book that serves both queries. The sequential `IntentGateway orderbook reads` suite, including a new pessimistic case, passes against the testnet orderbook on BSC Chapel and Polygon Amoy.
