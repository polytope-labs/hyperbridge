# Configuration

Everything here lives in `filler-config.toml`. The `[simplex]` block, its signer, the `[orderbook]` section and at least one `[[chains]]` entry are required. Everything else tunes behaviour that already has a working default.

## Where the config lives and what it contains

Simplex Desktop writes a new config into its per-user data directory:

| Platform | Default path |
|---|---|
| macOS | `~/Library/Application Support/Simplex/filler-config.toml` |
| Windows | `%APPDATA%\Simplex\filler-config.toml` |
| Linux | `$XDG_CONFIG_HOME/Simplex/filler-config.toml`, or `~/.config/Simplex/filler-config.toml` |

The npm binary looks for `./filler-config.toml`, then `$SIMPLEX_HOME/config.toml`; `-c <path>` selects
another file explicitly. Docker examples mount the file at `/data/filler-config.toml`.

<Callout type="warn">
    This file contains signing material in plaintext. On Unix, Simplex creates a new config atomically
    with mode `0600`; that blocks other OS users, not software already running as the operator. Windows
    has no equivalent mode bit. Keep the config out of source control, cloud-synced folders, and
    broadly shared backups, and restrict the containing directory to the operator account.
</Callout>

`simplex.substratePrivateKey` is a raw Substrate seed or mnemonic used to sign Hyperbridge bid
extrinsics, and it is required in **every** signer mode. Turnkey and MPC Vault protect the EVM signer,
but they do not remove this raw key from disk. Their API credentials are also stored in this file.

## `[simplex]`

```toml lineNumbers
[simplex]
# Optional — defaults to 5
maxConcurrentOrders = 5
# How often each chain is scanned for gateway events, in seconds.
# Optional — defaults to 3. Minimum 0.1.
blockScanIntervalSeconds = 3
# trace | debug | info | warn | error
logging             = "info"

# Required for solver selection
# Hex seed or mnemonic for Hyperbridge extrinsics
substratePrivateKey = "0x.."
# Hyperbridge WebSocket endpoint
hyperbridgeWsUrl    = "wss://nexus.rpc.polytope.technology"

# Order size in USD below which an order's fees must cover gas.
# Optional — defaults to 20. 0 never checks fees.
minOrderSizeUsd     = 20

```

`minOrderSizeUsd` decides which orders must pay for their own execution. An order worth less than this is skipped unless its `order.fees` cover the fill gas plus, for a cross-chain order, the relayer fee. An order worth at least this much is filled whatever fees it carries, and the margin in your limit order's rate pays for the gas. Raise it if gas on your chains costs more than that margin earns on a $20 fill. An order Simplex cannot value in dollars is treated as below it.

## `[orderbook]`

Simplex has no prices of its own. It prices every fill from your [limit orders](/developers/evm/simplex/limit-orders), and advertises them on the HyperFX orderbook this section points at. The section is required, and the setup wizard writes it for the network you choose.

```toml lineNumbers
[orderbook]
url = "https://orderbook.hyperfx.finance/mainnet/graphql"
# testnet: https://orderbook.hyperfx.finance/testnet/graphql

# Optional — the defaults are shown
defaultTtlSecs        = 31536000  # lifetime of a new limit order (365 days). Minimum 900.
reconcileIntervalSecs = 300       # how often postings are checked against the orderbook
requestTimeoutMs      = 10000     # per-request timeout for orderbook calls
```

| Field | Default | Description |
|---|---|---|
| `url` | none (required) | The orderbook's GraphQL endpoint. A base URL such as `https://orderbook.hyperfx.finance/mainnet` has `/graphql` added automatically. |
| `defaultTtlSecs` | `31536000` (365 days) | How long a limit order lives when it is created without its own `ttlSecs`. This is the order's whole life, and nothing renews it. Must be at least `900`, and the orderbook may enforce a higher minimum. |
| `reconcileIntervalSecs` | `300` | How often Simplex compares its open orders with the orderbook. It reposts any entry that has gone missing and cancels any entry no longer owned by an order. |
| `requestTimeoutMs` | `10000` | Timeout for each orderbook request. |

The limit orders themselves are not in this file. They are inventory you open and close while the filler runs, so they are stored in `bids.db` in the data directory and created from the dashboard or the [API](/developers/evm/simplex/api/limit-orders).

## `[[chains]]`

Each chain Simplex scans and fills on is one `[[chains]]` entry. At least one is required.

```toml lineNumbers
[[chains]]  # Base
rpcUrls = [
    "https://base-rpc.publicnode.com",
    "https://base.gateway.tenderly.co",
    "https://mainnet.base.org",
]
```

| Field | Default | Description |
|---|---|---|
| `rpcUrls` | none (required) | The chain's RPC endpoints, as a non-empty array. Each URL needs its own hostname. With more than one, event scans and confirmation counts are read through a [quorum](/developers/evm/simplex/confirmations#rpc-quorum). |
| `bundlerUrl` | none | Accepted and ignored. Simplex fills through [Hyperbridge's bundler](#bundler) for the chain. |

An entry names no chain ID. At startup Simplex asks each endpoint for its chain ID, and every endpoint that answers must report the same one. An endpoint that can't answer is kept, and the quorum judges it on each call. The chain fails to start only when no endpoint answers.

Reads outside the quorum go to the first healthy endpoint. These include balance reads, gas estimation and transaction submission. Put the endpoint you trust most first.

Use one endpoint per operator. Two URLs from the same provider agree with each other by construction, so the second adds nothing to the quorum.

### Free RPC endpoints

You don't need a paid provider to start. The endpoints below are free and need no account or API key. The setup wizards and the dashboard's Chains panel start each mainnet chain with the uncommented ones below. The commented ones also passed testing. A paid provider gives you more headroom, and you can list it alongside free ones.

Each endpoint scanned its chain alone for 20 minutes, as the only RPC, on 16–18 September 2026. The defaults then ran together in a quorum for 19 hours. All of them ran from one IP address. Free endpoints come and go, so watch your own logs.

When an endpoint rate-limits, Simplex sets it aside for as long as its `Retry-After` header asks, up to 5 minutes. An endpoint that falls behind the others is set aside for 15 seconds. The quorum is worked out over the rest, so one struggling endpoint costs nothing while enough of the others keep up.

Some free endpoints fail outright, so leave them out:

- Every `bsc-dataseed*` host refuses `eth_getLogs`. Simplex logs this as rate limiting, but it never clears, and a chain with only these endpoints never sees an order.
- `base.drpc.org` times out on `eth_getLogs`, and `arbitrum-one.public.blastapi.io` caps it at 10 blocks, fewer than one scan covers. Both providers work on the other chains listed.
- Tatum's gateways allow 5 requests a minute, and ZAN refuses `eth_getLogs` without an account.
- A URL with an API key in it, as endpoint directories publish them, shares one quota with everyone using it, and the key stops working without notice.

Some endpoints answer `curl` but refuse requests from Node, which Simplex uses. To try a new endpoint, run `simplex run --watch-only` with it as the chain's only `rpcUrls` entry, and watch the log for scan errors.

## Signer Configuration

The `[simplex.signer]` section defines how the binary signs EVM transactions. Four backends are supported:

The signer is a tagged union — set `type` to select the variant, then add the variant's fields directly under `[simplex.signer]`:

**Private Key** — Signs transactions locally using a raw private key:

```toml lineNumbers
[simplex.signer]
type = "privateKey"
key  = "0x..."
```

**Secret Phrase** — Signs transactions locally using one wallet derived from a BIP-39 secret phrase:

```toml lineNumbers
[simplex.signer]
type         = "secretPhrase"
phrase       = "word1 word2 word3 word4 word5 word6 word7 word8 word9 word10 word11 word12"
# accountIndex = 0  # optional, this is the default
```

The phrase must have 12, 15, 18, 21, or 24 words from the BIP-39 English wordlist and a valid checksum. The wallet is at `m/44'/60'/0'/0/accountIndex`, and `accountIndex` must be an integer from 0 to 2147483647. The phrase is stored in this file in plaintext, the same as a private key.

**MPC Vault** — Signs transactions via [MPC Vault](https://mpcvault.com), an institutional custody service that uses MPC for signing ceremonies:

```toml lineNumbers
[simplex.signer]
type                          = "mpcVault"
apiToken                      = "your-api-token"
vaultUuid                     = "your-vault-uuid"
accountAddress                = "0xYourWalletAddress"
callbackClientSignerPublicKey = "ssh-ed25519 AAAA..."
# grpcTarget = "api.mpcvault.com:443"  # optional, this is the default
```

<Callout type="info">
MPC Vault requires an Ed25519 keypair registered in the MPC Vault console and a running client-signer container (<code>ghcr.io/mpcvault/client-signer:latest</code>). See the <a href="https://docs.mpcvault.com">MPC Vault documentation</a> for setup instructions.
</Callout>

**Turnkey** — Signs transactions via [Turnkey](https://turnkey.com), a key management platform with HD wallet support. Create a wallet in the Turnkey Dashboard and use `signWith` to reference your existing Ethereum address:

```toml lineNumbers
[simplex.signer]
type             = "turnkey"
organizationId   = "your-org-id"
apiPublicKey     = "your-api-public-key"
apiPrivateKey    = "your-api-private-key"
signWith         = "0xYourWalletAddress"
```

<Callout type="info">
Create an API keypair in the Turnkey Dashboard under user details. The <code>signWith</code> field is any Ethereum address from your Turnkey wallet. See the <a href="https://docs.turnkey.com">Turnkey documentation</a> for setup instructions.
</Callout>

## Bundler

Fills execute as ERC-4337 UserOperations, which a bundler submits on chain. Simplex sends them through the bundler Hyperbridge runs for each chain, so there is nothing to configure. These bundlers need no API key and serve EntryPoint v0.8 and v0.9:

| Chain | Bundler |
|---|---|
| Ethereum | `https://bundler.polytope.technology/ethereum` |
| Base | `https://bundler.polytope.technology/base` |
| Arbitrum | `https://bundler.polytope.technology/arbitrum` |
| Polygon | `https://bundler.polytope.technology/polygon` |
| BNB Chain | `https://bundler.polytope.technology/bsc` |
| BSC Chapel (testnet) | `https://bundler.polytope.technology/bsc-chapel` |
| Polygon Amoy (testnet) | `https://bundler.polytope.technology/polygon-amoy` |

Simplex can only watch any other chain. It [refuses to fill there](/developers/evm/simplex/troubleshooting), so list such a chain under `watchOnly`. An older config's `bundlerUrl` is ignored.

## Delegation & Gas Payment

Simplex always uses the solver selection path: it submits a signed bid to Hyperbridge via `IntentsCoprocessor` rather than calling `fillOrder` directly. This requires `substratePrivateKey` and `hyperbridgeWsUrl` in `[simplex]`.

Solver selection requires each solver's EOA to be delegated to the `SolverAccount` contract. Simplex performs this automatically at startup via EIP-7702:

- **Primary path** — builds a no-op UserOperation with an attached EIP-7702 authorization and submits it through Hyperbridge's bundler for the chain. When a paymaster is deployed on the chain — Circle Paymaster (USDC) preferred, then the `SimplexPaymaster` (USDC or USDT), live on Ethereum, Arbitrum, Base, Polygon and BSC — see [Mainnet Contract Addresses](/developers/evm/contract-addresses/mainnet) — and the solver holds at least one whole token of a supported stablecoin, the paymaster pays gas in that stablecoin so the solver never needs native gas for delegation. Tokens with EIP-2612 are authorized by permit; tokens without it (such as BSC stables) need a one-time funded `approve(Permit2, max)` from the solver EOA, after which every operation carries a per-op Permit2 signature and no native gas is needed again.
- **Fallback** — if the bundler path fails or the chain has no paymaster, Simplex sends a direct type-0x04 delegation tx using the solver's native balance. On paymaster-less chains it also keeps the ERC-4337 EntryPoint deposit topped up to cover `targetGasUnits` (default 3,000,000) at the current gas price.

No manual steps are required — delegation is idempotent and skipped if the EOA is already delegated to the correct contract.

## Allowlist

The optional `[allowlist]` section restricts which order `user` addresses the solver will process. Omit the section entirely to accept orders from all users (the default). When present, only listed users are accepted; address comparisons are case-insensitive.

```toml lineNumbers
[allowlist]
# Users eligible across all source chains
users = [
    "0x1111111111111111111111111111111111111111",
]

# Per-source-chain overrides, keyed by state-machine ID.
# Merged with the global list.
[allowlist.bySource]
# Ethereum-only partner
"EVM-1"     = ["0x2222222222222222222222222222222222222222"]
# Arbitrum-only partner
"EVM-42161" = ["0x3333333333333333333333333333333333333333"]
```

A source chain whose merged set (global `users` + its `bySource` override) is empty rejects every order from that chain.

## Gas Fee Bump

UserOperation gas prices are bumped above the base `gasPrice` by configurable percentages. Defaults are `8%` for the priority fee and `10%` for the max fee. Override under `[simplex.gasFeeBump]`:

```toml lineNumbers
[simplex.gasFeeBump]
# added to base gasPrice for the priority fee
maxPriorityFeePerGasBumpPercent = 8
maxFeePerGasBumpPercent         = 10   # added to base gasPrice for the max fee
```

## Block scan interval

Each configured chain is polled for gateway events on its own interval, set by **`blockScanIntervalSeconds`** under `[simplex]`. It defaults to **3 seconds** and must be at least `0.1` — a zero or negative value would spin the scanner as fast as the event loop allows and exhaust an RPC budget in minutes, so it is rejected at startup rather than left for `setInterval` to coerce.

The interval is the main lever on RPC spend. Each tick costs one `eth_blockNumber` plus one `eth_getLogs` per chain, per endpoint in that chain's quorum — so halving the interval doubles the request rate against every provider. Lower it if you are losing orders to faster solvers; raise it if you are being rate-limited.

```toml lineNumbers
[simplex]
# Poll twice a second — faster pickup, ~6x the requests of the default.
blockScanIntervalSeconds = 0.5
```

Orders are still evaluated against the confirmation policy after they are seen, so a shorter interval brings detection forward but does not change how long a cross-chain order waits before it can be filled.
