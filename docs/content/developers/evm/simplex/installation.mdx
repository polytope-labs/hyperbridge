# Installation

Simplex Desktop is the recommended way to run a solver on a personal workstation. It bundles the
solver, dashboard, and matching Node runtime in one application, keeps running from the system tray,
and does not require npm or Docker. macOS and Windows builds install authenticated updates; Linux
updates remain manual until the release metadata has its own signature.

## Desktop app (Recommended)

[Open the Simplex Desktop releases](https://github.com/polytope-labs/hyperbridge/releases?q=simplex-desktop-v&expanded=true),
choose the newest stable `simplex-desktop-v…` release, and download the installer for your machine:

| Platform | Download |
|---|---|
| macOS, Apple silicon | `Simplex-<version>-mac-arm64.dmg` |
| macOS, Intel | `Simplex-<version>-mac-x64.dmg` |
| Windows, x64 | `Simplex-<version>-win-x64.exe` |
| Linux, x64 | `Simplex-<version>-linux-x86_64.AppImage` or `Simplex-<version>-linux-amd64.deb` |
| Linux, arm64 | `Simplex-<version>-linux-arm64.AppImage` or `Simplex-<version>-linux-arm64.deb` |

Open Simplex after installation. On macOS and Windows, select **Create passkey**, then
**Create passkey** in the browser and approve Touch ID or Windows Hello. Return to Simplex,
save the recovery code, and confirm it. **Use a password instead** is available; Linux uses passwords.
The setup wizard then writes an encrypted `filler-config.toml` into the app's per-user data directory:

| Platform | Default desktop config |
|---|---|
| macOS | `~/Library/Application Support/Simplex/filler-config.toml` |
| Windows | `%APPDATA%\Simplex\filler-config.toml` |
| Linux | `$XDG_CONFIG_HOME/Simplex/filler-config.toml`, or `~/.config/Simplex/filler-config.toml` |

Every fresh desktop launch requires authentication. Existing password profiles can enable
**Create a passkey for future logins** while signing in, retaining their password fallback.
**Recover access** accepts the saved recovery code to replace an unavailable passkey; save the new
recovery code before continuing. Cancelled prompts leave the dashboard locked and can be retried.

Closing the window leaves the solver running in the tray. Use **Quit Simplex (solver keeps filling)**
to close only the app, or **Stop solver and quit** to stop both. Simplex Desktop tracks the same
version as `@hyperbridge/simplex`, so the version shown in the app identifies the bundled solver too.

<Callout type="warn">
    Desktop encrypts its config at rest; CLI and Docker configs contain private keys and credentials
    in plaintext. Software running as your OS user remains within the desktop's trust boundary.
    Back up both `filler-config.toml` and `desktop-vault.json` and keep the recovery code somewhere
    private. A synced passkey alone cannot restore the config on another machine or OS account.
    `simplex.substratePrivateKey` is required in every signer mode, including Turnkey and MPC Vault.
    See [Configuration](/developers/evm/simplex/configuration#where-the-config-lives-and-what-it-contains).
</Callout>

### What the PWA is for

The install action in the browser dashboard remains available for remote and mobile access to an
existing solver, especially through the authenticated tunnel. The PWA is only an offline-capable UI
shell: it does not contain the solver or cache live balances and activity, and it needs the solver API
when it reconnects. Use Simplex Desktop for the local double-clickable application.

## Advanced: Docker

The image is a multi-arch manifest covering `linux/amd64` and `linux/arm64`, so Linux, macOS (Intel and Apple Silicon) and Windows (Docker Desktop / WSL2) hosts all pull a natively-built image — no emulation, no per-host build.

```bash lineNumbers
docker pull polytopelabs/simplex:latest
docker run --rm -it polytopelabs/simplex:latest --help
```

Starting with no config puts the container into the setup wizard. Publish the UI port and give it a volume to write the generated config into:

```bash lineNumbers
docker volume create simplex-data
docker run -d --name simplex --restart unless-stopped \
    -p 127.0.0.1:8686:8686 \
    -v simplex-data:/data \
    polytopelabs/simplex:latest
```

Then open `http://localhost:8686`. The wizard writes `filler-config.toml` into `/data` and transitions straight into running the solver; on restart the container finds that config and runs directly. Mount a config you already have with `-v /path/to/filler-config.toml:/data/filler-config.toml:ro` to skip the wizard, or run it in the terminal instead with `docker run --rm -it -v simplex-data:/data polytopelabs/simplex:latest init -o /data/filler-config.toml`.

The command works verbatim in PowerShell on Windows (use a backtick instead of `\` for line continuations, or put it on one line). Ports have to be published — the container binds `0.0.0.0` internally because Docker Desktop on macOS and Windows runs the daemon inside a VM and offers no `--network host`. The container's network namespace is the boundary there, so keep the `127.0.0.1:` prefix on the published ports: the UI is unauthenticated, and the wizard handles private keys.

## Advanced: npm binary

Use the npm distribution for a terminal-managed process or when integrating Simplex with an existing
Node deployment:

```bash lineNumbers
npm install -g @hyperbridge/simplex
simplex
```

The scope matters: the unscoped `simplex` package on npm is unrelated. The installed command is still
`simplex`. A global install needs Node.js 22.16 or newer; the desktop and Docker distributions bundle
their own runtime.

## Building a config file

The fastest way to produce a working `filler-config.toml` is one of the interactive wizards:

```bash lineNumbers
simplex          # browser wizard: opens automatically when no config exists
simplex init     # the same flow in the terminal
```

Both ask only for the minimum needed to run: chains, signer and Hyperbridge account. Each mainnet chain starts with a set of public RPC endpoints, which you can replace, and fills through the [Hyperbridge bundler](/developers/evm/simplex/configuration#bundler), which neither wizard asks about. They point the `[orderbook]` section at the HyperFX orderbook for your network, and explain each value as they ask for it. Neither asks for prices. Once the solver is running, you set those by posting [limit orders](/developers/evm/simplex/limit-orders) from the dashboard. The browser wizard can also generate the Substrate account for bids and check its BRIDGE balance; when it finishes, the same process transitions straight into running the solver — no restart. A local web UI (status, pause/resume, balances, limit orders) stays available at `127.0.0.1:8686` while the solver runs (`--no-ui` for headless). Prefer a file-first workflow? Use the reference config below.

<Tabs items={["docker-compose.yml", "config.toml"]}>
<Tab value="docker-compose.yml">
```yaml lineNumbers
# Identical on Linux, macOS and Windows: `docker compose up -d`
services:
    simplex:
        image: polytopelabs/simplex:latest
        container_name: simplex
        restart: unless-stopped
        command:
            ["run",
             "--config", "/data/filler-config.toml",
             "--data-dir", "/data",
             "--ui", "0.0.0.0:8686"]
        ports:
            # web UI (unauthenticated — keep it on loopback)
            - "127.0.0.1:8686:8686"
        volumes:
            - simplex-data:/data # bids database + runtime state
            - ./filler-config.toml:/data/filler-config.toml:ro
        logging:
            driver: "json-file"
            options:
                max-size: "10m"
                max-file: "3"

volumes:
    simplex-data:
```
</Tab>
